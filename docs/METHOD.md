# 官方地圖地理校準方法論

如何把「沒有地理座標的 3D 手繪雪場地圖」對位到真實經緯度，讓 GPS 位置可以疊上去。
以藏王溫泉雪場為例，全流程自動化，不需任何手動校正。

## 核心難題

日本雪場官方地圖幾乎都是 **3D 鳥瞰手繪插畫**。實測量化（藏王）：

| 區域 | 畫家比例尺 vs 真實 |
|---|---|
| 山頂稜線 | 相對一致（±30px ≈ 25m） |
| 市街區／山麓基地 | 與山頂區比例尺完全不同（同一變換下誤差 >1km） |

結論：**單一全局變換（homography / affine / poly2）在數學上不可能成立**——
這不是控制點不夠多，是畫法本身是「蒙太奇」：不同區域用不同比例尺繪製。
SIFT 特徵匹配也會失效：風格化插畫與 OSM 線稿的視覺域差距太大。

## 解法：TPS 非剛體配準 + 由內向外 ICP

```
OSM 向量資料 (piste:type + aerialway 幾何)
        │  equirectangular 投影渲染
        ▼
參考線稿圖 ──3 個驗證山峰 bootstrap──▶ 初始相似變換 T0
        │
        ▼
ICP 迭代（閾值逐輪放寬 6→50px，由山頂向外生長）：
    每輪：投影 OSM 點 → 距離變換取最近地圖邊緣 → 只信任貼合好的點
    → TPS 擬合位移場（正則化 λ = n·2e-3 防塌縮）→ 全點重投影
        │
        ▼
藏王實測：3,300 點中 1,682 點收斂，平均貼合誤差 27px ≈ 31m
        │
        ▼
TPS 模型（1682 控制點 + 權重，68KB JSON）隨 App 發佈
執行時 GPS → 公尺座標 → TPS 評估 → 地圖像素，單次 <0.1ms
```

### 為什麼有效

- TPS 的平滑正則化讓變形場「逐區彎曲」吸收蒙太奇失真，而非強套全局模型
- 由內向外的閾值生長避免離群點污染：初始只在已驗證的山頂區信任配對，
  對位穩定後才逐步納入更遠的區域
- 距離變換（Canny 邊緣的 DT）天然容忍「細線 vs 寬帶」的風格差異

### 曾經失敗的方法（記錄避免重蹈）

| 方法 | 失敗原因 |
|---|---|
| SIFT + RANSAC homography | 插畫 vs 線稿特徵無對應；且 3D pano 不服從單一 homography |
| Chamfer + 網格搜尋 | 退化解：所有線段擠進低邊緣密度區「得分」（需散佈懲罰＋最小 scale 限制） |
| Homography on 3+1 控制點 | 3 個山峰共線（同稜線）→ 變換退化 |
| 全局 poly2（6 點） | 控制點間劇烈振盪：刈田リフト距山頂 300m，投影卻偏 846px |

## 新增雪場的步驟

1. **找官方地圖**：官網 PDF 或高解析圖（≥2000px），存入 `atlas/raw/`
2. **渲染**：`pymupdf` 以長邊 3000px 轉 PNG/JPG
3. **撈 OSM 幾何**：Overpass 查該雪場 bbox 的 `piste:type` + `aerialway`（`out geom`）
4. **Bootstrap**：認出 2–3 個 OSM 有座標的特徵在地圖上的位置
   （山峰三角、命名纜車站——用 `stitch-osm.py` 渲染帶經緯网格的 OSM 對照圖輔助）
5. **跑配準**：參考 `zao-register.py`（bootstrap 相似變換 → TPS-ICP）
6. **驗證**：疊圖目檢紅點是否沿真實雪道分佈；殘差 <50px 為合格
7. **發佈**：TPS 模型存 `atlas/<id>-tps.json`，manifest 加入該雪場

## 精度期望

| 地圖類型 | 可達精度 |
|---|---|
| 平面 2D 圖（有明確地標） | 20–50m |
| 細節型 3D 圖（如 Grand Hirafu，8 控制點 poly2） | ~33m |
| 全景型 3D 圖（如 Zao，TPS 自動配準） | 30–100m（核心區），邊緣外推較弱 |

GPS 本身戶外極限 2.5–5m（雙頻晶片 1.5–2m），樹林/陡坡退化至 10–20m——
因此 30m 級的地圖校準已足夠支撐「我在哪條雪道」等級的定位。

## 工具腳本

- `scripts/fetch-resorts.mjs` — Overpass 抓全日本雪道聚類成雪場偵測庫
- `scripts/stitch-osm.py` — OSM 圖磚拼接＋經緯网格（bootstrap 對照用）
- `scripts/calibrate.py` — poly2/poly3/homography 擬合＋殘差報告＋驗證疊圖
- `scripts/zao-register.py` — TPS 非剛體配準完整管線（其他雪場的範本）

## 藏王全山 TPS：2026-08-26 深度驗證記錄（未採用，附原因）

嘗試以 OSM 雪道/纜車線幾何做全山非剛體配準，經嚴格驗證後回退：

1. **單位契約**：校準（Python）與執行時（JS）的公尺座標定義必須逐位一致
   （含是否乘 cos(lat)）。曾因不一致導致線上投影爆炸（點落在 21 億像素外）。
2. **hold-out 洩漏陷阱**：控制點密集時，「每 4 取 1」式留出會被鄰居插值作弊，
   得到假 0.1–1.7m 數字。必須整區塊（400m 網格）移除＋控制點稀疏化（≥60m）。
3. **留一錨點交叉驗證（LOO）才是真精度**：
   - OSM 線幾何參與擬合時，LOO 誤差 277–1889m——線幾何污染整個形變場
   - 純權威點錨點（Nominatim 峰頂×3＋MapFan/geocoding.jp 山麓駅＋視覺地藏岳）
     LOO 仍達 ~389m——部分錨點的「地圖像素端」定位誤差太大（風格化全景圖上
     目視定位 ±50–200px）
4. **資料品質事實**：本區 OSM aerialway 幾何多處與真實矛盾
   （山頂線端點、不存在方位的纜車線），piste 線未驗證；不可當配準地面真值。

**結論**：遙距自動管線的可信極限＝三峰相似變換（稜線區 ±25m 級，OCR 獨立
驗證熊野岳錨點誤差 30px）。達到 5m 的正確路徑是**實地 GPS 軌跡校準**：
每次實滑的軌跡即數百個地面真值點，對地圖特徵做彈性配準——這需要使用者實測資料。
